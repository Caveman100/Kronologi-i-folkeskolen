# CLAUDE.md

**Epoke – før eller efter?** (short name: **Epoke**; this is a *working title* and may change, so keep the name easy to swap out) is a Danish card game about chronology for primary schools (folkeskolen). Players place event cards in order on a shared timeline. It was formerly called "Historiens Tidslinje" and was renamed to stay clear of the commercial game *Timeline*. Do not reintroduce "Timeline" or "Tidslinje" as the game's name. "tidslinjen" as an ordinary noun in the rules and UI is fine. The PeerJS room prefix `v3-historiens-tidslinje-dk-` in the bundle is internal; leave it alone, because changing it would stop old and new clients from finding each other.

**Ask when in doubt.** If a request is unclear, can be read in more than one way, or clashes with a rule in this file, ask the user before acting. When you ask, offer two concrete suggestions to choose between (and say which one you recommend). Don't guess on content (card texts, sources, images) or on anything that touches the Jul set.

Planned editions: this one for schools comes first. Later there will be a casual online-for-fun edition and possibly a museum or exhibition edition. Keep changes edition-friendly, for example by keeping branding and content separate from the game logic. It is a static site with no build step, hosted on GitHub Pages (`.nojekyll`, remote `Caveman100/Kronologi-i-folkeskolen`). All user-facing text, card content and commit messages are in Danish.

## Layout

The user knows Python/R but has limited HTML/CSS/JS experience. Keep code readable for them: Danish comments, settings in the settings files rather than hard-coded, and `LÆS-MIG.md` (the user-facing overview) up to date when the structure changes.

- `index.html` holds only the HTML: the screens (`scr-home`, `scr-settings`, `scr-quiz`, `scr-quizcat`, `scr-quizset`, `scr-learn`, `scr-local`, `scr-host`, `scr-join`, `scr-wait`, `scr-game`), overlays and dialogs (`ov-rules`, `deck-menu`, `year-dialog`, quit dialog), the `#wiki-credits` dialog ("Kilder", whose music and per-card image credits are hard-coded HTML on one long line), and the `<link>`/`<script>` tags. The `<script src="sets/*.js">` order is the order of the "Vælg kortsæt" menu, and the first set is the default.
- `indstillinger.js`: `window.EPOKE_INDSTILLINGER` (timings such as `visResultatMs`, hand sizes (players choose them under Indstillinger, stored as `htl-haand-duel` / `htl-haand-quiz` via `EpokeQuiz.handSize`; defaults `kortPaaHaanden` 5 for Duel through the `R.hand` getter, `quizKortPaaHaanden` 3 for Mestring and Overlevelse, max `maksKortPaaHaanden`), card sizes `kortStoerrelse` {egne, tidslinje, modspiller} in % that become the CSS vars `--skala-*` multiplied into `--hw/--tw/--ow`, hand size, swaps, year guess, music volume, relay URL) plus the `?relay=` handling that sets `window.HIST_RELAY` and `window.EPOKE_RELAY_URL`. The bundle reads it as `INDST.<name> ?? <old default>`. Put new tunables here rather than hard-coding them.
- `css/skrifttyper.css` (`@font-face` → `fonts/*.woff2`), `css/indstillinger.css` (the single `:root` block: colours, fonts, image URLs, card sizes `--hw/--tw/--ow`, SVG frames), `css/spil.css` (everything else, in 25 numbered "DEL" sections). `spil.css` is layered: later sections override earlier ones, so never reorder sections; edit the last matching rule. URLs in `css/` are relative to `css/` (`../images/...`); `applyLook` turns a set's `background` into an absolute URL for that reason.
- `js/kortsaet.js`: the **set registry** (`window.TimelineSets`, `registerSet`), readable.
- `js/spil.js`: the game itself, a **minified esbuild bundle** with PeerJS inlined; the source is not in the repo. It starts with a Danish table of contents and a glossary of the short names (`k` state, `B` act, `Ne` reducer, `I` render ...), and has section banners. Hand-written readable parts: the relay client (`roomSocket`, `keepAlive`, `RelayHost`, `RelayGuest`), `advanceWhenReady`, drag and drop, and everything from `leaveTable` to the end (music, `window.__game`).
- `js/sne.js` (canvas snow for sets with `snow: true`) and `js/tur-boks.js` (`window.showTurnBox`).
- `js/kort-info.js` (readable): the info box to the right of a card, shown on mouse hover (`kortInfoHoverMs`) or touch long-press (`kortInfoLangtTrykMs`; the click on release is swallowed). It shows `desc` plus any `tip` text before `Kilder:`, in the card's frame colours (CSS: `spil.css` DEL 24). On Lær the whole row is the hover target. The (?) dialog (`openInfo` in `js/spil.js`) shows only the title, the `tip` part from `Kilder:` (Jul: `more` once revealed) and the "Læs mere" links.
- `js/quiz.js` + `css/quiz.css`: the solo Quiz part (readable). Builds the quiz screens, the home-screen progress row and Lær, and owns the saved scores (`window.EpokeQuiz`). The quiz rules live in `js/spil.js` in the hand-written block "QUIZ: SPIL (TILSTAND A) OG ØV FEJL", which exposes `window.EpokeGame` (`startQuiz`, `startSurvival`, `card`, `info`, `fit`, `year`, `screen`) for `quiz.js`. Decisions and the rejected alternatives: `docs/beslutninger-quiz.md`.
- `LÆS-MIG.md`: overview for the user (Danish).
- `sets/*.js` hold the card sets. `sets/kanon.js` holds the 30 Historiekanon cards; they also appear in Classic through `include`. Each file calls `registerSet({...})`.
- `images/<setId>/` holds the card images. The table and UI textures (`bord*.jpg`, `egetrae.jpg`, `kortbagside.jpg`, `titel.jpg`, `baggrund.jpg`) sit directly in `images/`.
- `music/` holds the MP3s: `fiddle-de-dee.mp3` (Shane Ivers, CC BY 4.0) plays once from 34.2 s with a fade-in when the home screen shows, carries on through the menus and fades out when a game starts (settings `forsideMusik*`); `the-old-tower-inn.mp3` (RandomMind, CC0) loops during games and in the menus once the home track has ended. A set with its own `music` (Jul) replaces it during that set's games.
- `relay/` holds the online relay: a Cloudflare Worker with one Durable Object per room (`relay/src/index.js`, `relay/wrangler.toml`, deploy guide in `relay/README.md`). It is deployed separately with `npx wrangler deploy`; GitHub Pages does not run it.

## Card sets (`sets/*.js`)

Set options: `id`, `name`, `description`, `startCards` (how many cards lie on the table at the start: each game draws that many at random, one from each equal slice of the year-sorted deck, via `pickStartCards` in `js/kortsaet.js`; sets in the setting `fasteStartkort` (Jul) keep the listed ids; Øv fejl never uses missed cards as start cards), `images` (folder, default `images/<id>/`), `cards`. Optional: `combine: true` (no cards of its own; pulls in every set except those with `inTotal: false`), `inTotal: false`, `menu: false`, `include: ["<setId>", ...]` (the deck also gets those sets' cards; Classic uses `include: ["kanon"]`), `reuse: ["<cardId>", ...]` (the deck also gets these single cards from other sets, without duplicating them; used by the `sets/klasse*.js` sets), `menuColor: "r, g, b"` (gives the set's button in "Vælg kortsæt" a muted tint of that colour; the Alinea sets use Alinea's history portal colour `189, 91, 0`), `menuStyle: "home"` (gives the set's button the same leather look as the home-screen buttons; used by Historiekanon and Historie), `quizCategory` (groups sets into one Quiz category; the Alinea sets use `"Alinea"`; without it a set is its own category), `quizIcon` (the character in the set's round seal in the Quiz menus; default is the first letter of the name), `background`, `snow`, `music`, and `credits: {music, html}` (injected into the Kilder dialog).

Card fields: `id`, `year` and `title` are **required**. Card ids must be unique across *all* sets, and duplicates are logged to the console and skipped. Negative years mean BC. Other fields:
- `desc`, `tip`. `desc` is shown in the hover info box, which can be opened *before* the card is placed, so never put the event's year in `desc`. `tip` no longer holds hint text (removed from all sets except Jul); it holds only the card's sources: `Kilder:` followed by one APA reference per line (the (?) text keeps line breaks, `\n`). Jul cards keep their old `tip` and also have `more`, which is shown in place of `tip` after the card is revealed.
- `era`: picks the card colors from a hard-coded map in the bundle. The known eras are Forhistorisk tid, Oldtidens Egypten, Antikken, Middelalderen, Renæssancen, Opdagelsernes tid, Videnskabernes tid, Oplysningstiden, 1800-tallet, 1900-tallet and 2000-tallet. Any other era falls back to grey.
- `category`: `"Maleri"` gives the image the `art-original` styling (not cropped).
- `canon`, and `label` (for example `"Historiekanon"`, which is shown on the card instead of the set name).
- `approx: true` marks the year as approximate. The bundle also hard-codes some approximate ids: buddha, pyramiderne, solvognen, harald-blaatand, jesus, tutankhamon.
- `image`: a file name relative to the set's `images` folder, or an absolute or `data:` URL.
- `emoji`.
- `sources`: 1–2 links, `[{"title": "Historiekanon – emu.dk", "url": "https://…"}]`, shown as "Læs mere" links under the (?). Link the main source; add a second only when it carries something important, such as the year. Cards without `sources` show the Wikipedia link instead.
- `wikiTitle`, or `wiki` (a full URL), for the Danish Wikipedia link. Only used when the card has no `sources`.
- `prompt` is an image-generation prompt kept for reference. The game does not use it.

## Content rules for cards (the user's standing preferences)

**The Jul (Christmas) set is exempt.** None of the rules below apply to `sets/jul.js`, `images/jul/` or the Jul music and credits. Do not change anything in the Jul set (cards, images, music, credits or set options) unless the user explicitly asks for that specific change. This includes not "fixing" it to match these rules, and not touching it as part of changes to other sets.

- **Open source, always.** This is a rule, not a preference. Images, music and any copied text must have an open license (public domain, CC0, CC BY or CC BY-SA). Sources that are cited must be freely accessible online, with no paywall or login. That covers Danish educational publishers too: only cite their open material.
- **A source for everything.** Every fact, image and piece of music must have a source. Nothing goes in without one.
- **Sources on every card.** Each card's info text, shown behind the (?), must show its source(s). That text is `tip`, which holds only the sources. When a source is linked (in `sources` on the card, or as `<a>` in the Kilder dialog), leave the web address out of the reference text: the link is enough. Never show both.
- **APA everywhere.** Write the sources in APA style, both on the cards (?) and in the "Kilder" dialog (`#wiki-credits` and set `credits`).
- **Pick the best source available**, by tier:
  - **S-tier, top:** EMU's Historiekanon page: https://emu.dk/grundskole/historie/historiekanon/historiekanon. It is the first source for every canon card (`sets/kanon.js`). Its text is CC BY-NC-SA, so cite it and write in your own words; don't copy it.
  - **S-tier:** official Danish sources: Børne- og Undervisningsministeriet, EMU (emu.dk), Danmarks Statistik (DST) and CFU. Also the subject guides (faghæfter) on EMU, above all the history guide: https://emu.dk/sites/default/files/2023-06/gsk_historie_fagh%C3%A6fte_2023.pdf. Also Danish educational publishers, both books and online material.
  - **A-tier:** other recognised sources in language the pupils can easily read, such as museums, Lex.dk (Danmarks Nationalleksikon) or other countries' official authorities. Lex text is "begrænset genbrug": cite it, don't copy it.
  - **B-tier:** Wikipedia. Use it only when no S- or A-tier source covers the fact.
- **Stay close to the sources.** Keep the card text as close to what the source says as possible, but in simple language for folkeskole pupils.
- **General titles, concrete descriptions.** Players must be able to place a card without knowing the specific name. So when it is possible without bending the history, the `title` names the broader development and the `desc` or `tip` names the concrete event. Example: "Vikingerne angriber Lindisfarne" becomes "Vikingetiden begynder". The description still says that the attack on Lindisfarne in 793 was the first Viking raid on England and is counted as the start of the Viking Age. How general a title should be is weighed case by case: sometimes a well-known name (Gandhi, Magna Carta) is better than a vague title, and a general title must still fit the card's year (for example "Islam grundlægges" moved the card from 622 to about 610). Suggest title changes one card at a time and let the user decide.

To add a set: create `sets/<id>.js` and `images/<id>/`, then add a `<script src="sets/<id>.js">` line before `sets/jul.js` or wherever it belongs in the menu. `LÆS-MIG.md` (referenced from the first line of the set files) explains this for the user.

## Game features (in the bundle)

- The home screen is titled **"Før eller efter?"** (the old "Epoke" heading was dropped there; `<title>` is unchanged). Its buttons are **Quiz** ("Mester historien"), an **Indstillinger** text link (`scr-settings`: Vælg spillere for Duel, plus on/off switches for optional sets), **Duel** (local hot-seat; the small text follows the player count), **Opret online spil** and **Deltag med kode**. The "Din fremgang" row (the average over all quizzes) sits at the top of the Quiz screen.
- **Optional sets:** `valgfrieKortsaet` in `indstillinger.js` (currently `{ jul: false }`) lists sets that players can switch on and off under Indstillinger. A player's choice is stored as `htl-saet-<id>` and overrides the default. Hidden sets are left out of "Vælg kortsæt" and the Quiz menu (`TimelineSets.shown`). `sets/jul.js` is always loaded; Total and Art are still commented out in `index.html`.
- **Quiz** (Seterra-style, solo): a quiz is one set (shown if the set is loaded and not `menu: false`); categories come from `quizCategory`. Each quiz page has only **Spil** and **Lær**, plus the best score for the chosen mode. **Spil** starts the quiz mode chosen under Indstillinger (`htl-quizTilstand`, default `quizTilstand` in `indstillinger.js`, currently Overlevelse): Mestring or Overlevelse.
  - **Mestring** (mode `"quiz"`): the player holds several cards (the Quiz hand size) but the `quizForsoeg` (3) tries belong to one card: after a wrong try the other cards are locked (note `"lock"`) until that card is placed. Tries, and the year is never shown after a miss. After the last miss the right gap turns green and the player places the card there. Only first-try placements count as right, and an exact year counts only on those. Enter in the year field places the card where the guessed year belongs. Ranking: % right, then exact years, then time.
  - **Overlevelse** (mode `"infinite"` with `fromQuiz`): one mistake ends the run, and the best result is saved per set as placed/total.
  - **Lær**: every card in order with its year and the full `desc` (no hover box there). Tapping a card opens the (?) dialog with the sources.
  - **Øv fejl**: offered only as a button on the end screen right after a Mestring game with misses; replays only those cards. It never changes the saved %.
  Scores live in `localStorage` as `htl-quiz-<setId>` = `{a:{right,exact,total,ms}, b:{placed,total}, m:[missed ids]}`, always built by `scoreKey()` in `js/quiz.js` so profiles can be added in one place. The old global `htl-infiniteBest` is only used if Overlevelse is started outside Quiz (no button does that any more).
- Optional year-guess dialog in the 2-player game.
- Online play using a 4-letter room code that the host shares. If players lose the connection, they can rejoin with the same code. By default all traffic goes over WebSocket (HTTPS port 443) through the Cloudflare relay in `relay/`, so it works behind school firewalls; the relay generates the room code. `?relay=ws://localhost:8787/room` points at a local `wrangler dev`; `?relay=off` falls back to the old PeerJS (WebRTC) path. Relay and PeerJS clients cannot find each other. If you change the relay protocol, change the Worker and `RelayHost`/`RelayGuest` together and redeploy the Worker before pushing `index.html`.
- Settings and scores are saved in `localStorage` under keys prefixed `htl-`.
- Each set changes the look through body classes `set-<id>`, `set-bg` and `set-snow`, and the CSS variable `--set-bg`.

## Working here

- To run it, open `index.html` in a browser or serve the folder (for example `python -m http.server`). There is no linter or package manager.
- **Show a screenshot before any visual change is kept.** This covers anything graphical: CSS, layout, colours, shadows, images, card look. Make the change as a proposal, take before and after screenshots in headless Edge or Chrome, save them as PNG files and give the user their full paths. Then wait for the user's approval. If the user says no, revert the change.
- **Test after every change that isn't trivial.** Whenever you change code, set structure, card ids, images or anything beyond small text edits, write and run tests that show the game still works, and report the results. At minimum:
  - Load the set registry and every `sets/*.js` in Node, and check that each set builds a deck, the start cards are in the deck, there are no duplicate ids, every card has `id`, `year` and `title`, and every image file exists.
  - Run the game headless in a browser (Edge and Chrome are installed): start a game with the changed set, and open the (?) dialog on some cards. Check that no JavaScript errors occur and that the change shows up as intended.
  - If a test can't be run, say so and why. Small pure-text changes (a card's wording, a typo) don't need the browser test, but still need the Node check if a `sets/*.js` file was touched.
- Most content edits happen in `sets/*.js` (JSON-like card objects, one per line) plus images in `images/<set>/`. When adding or replacing images, also update the credits in the `#wiki-credits` dialog in `index.html`. Only use images with a free license; Jul images without one were replaced by the card back.
- Avoid editing the minified bundle (`js/spil.js`) unless necessary. If you must, make small, targeted string edits, and never insert text inside a template literal or string (check with `node --check`, and use a backtick-in-comment probe when adding comments). Older full versions (`tidslinje-wiki_*.html`) live in the parent folder outside the repo.
- Use Grep with a narrow pattern, or Read with offset and limit, on `js/spil.js` and on the `#wiki-credits` line of `index.html`. Many lines in `js/spil.js` are several KB to 45 KB long.
- CSS refactors: verify "no visual change" by dumping `getComputedStyle` for every element (and `::before`/`::after`) in a set of game states before and after, and diffing; screenshots alone miss small changes.
